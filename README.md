# 电力技术规范智能问答助手

>
> 基于 RAG 检索增强生成技术的电力行业垂直知识库问答系统

本项目是一套面向电力行业的技术规范智能问答解决方案，通过大语言模型与向量检索技术，实现电力标准文档的精准问答、自动类目匹配、知识库可视化管理等能力。支持 PDF / DOCX 格式规范文档一键入库，系统自动识别技术分类并基于原文生成严谨回答，有效降低规范查阅成本，提升技术人员工作效率。

项目采用 Spring Boot + Vue 3 前后端分离架构，支持一键合并打包为单 Jar 部署，适配政企项目驻场交付、内网私有化部署场景，界面采用国网行业通用的浅绿视觉体系。

---

## ✨ 功能特性

### 核心能力

- **智能问答**：基于 RAG 检索增强生成，回答严格依据上传的规范文档生成，大幅减少大模型幻觉，回答可溯源
- **自动分类匹配**：文档上传与用户提问均由 AI 自动识别所属技术类目，对用户完全屏蔽分类概念，使用零门槛
- **知识库可视化管理**：支持 PDF / DOCX 格式文档上传，自动切片向量化入库；提供上传历史记录，切换页面不丢失
- **扫描件兼容**：原生支持电子版 PDF/Word 文本提取，可通过阿里云 OCR 扩展支持扫描件 PDF 识别入库
- **对话持久化**：对话历史本地缓存，页面切换、浏览器刷新均不丢失对话记录
- **长任务适配**：针对 OCR、向量化等长耗时场景，上传接口放宽超时限制，前端提供实时等待提示与取消能力
- **结构化输出**：回答自动按规范条文格式输出，符合电力行业专业阅读习惯

### 工程特性

- **前后端一体部署**：支持开发期分离调试、打包期自动合并，最终产出单个可执行 Jar，部署零依赖
- **多模型解耦配置**：对话模型、嵌入模型、OCR 服务独立配置，默认 DeepSeek 对话 + 通义千问嵌入 + 阿里云 OCR，可灵活替换其他兼容 OpenAI 协议的模型
- **国网风格界面**：采用电力行业主流浅绿配色体系，界面简洁专业，符合政企系统视觉规范
- **平滑升级路径**：内存向量库可无缝升级为 Milvus 持久化向量库，业务代码零改动
- **配置安全规范**：敏感密钥采用示例配置 + 本地配置分离模式，支持环境变量注入，避免密钥误提交代码仓库

## 🛠 技术栈

### 后端

- **框架**：Spring Boot 3.2.x
- **AI 能力**：Spring AI 1.0.x
- **大模型**：DeepSeek Chat（对话生成）、通义千问 Embedding（向量向量化）
- **OCR 能力**：阿里云印刷文字识别（可选，用于扫描件 PDF）
- **向量存储**：SimpleVectorStore（内存版，开发调试）/ Milvus（持久化版，生产环境）
- **文档解析**：Apache PDFBox、Apache POI
- **构建工具**：Maven

### 前端

- **框架**：Vue 3 + Vite
- **UI 组件**：Element Plus
- **HTTP 客户端**：Axios
- **状态管理**：Composition API 响应式全局状态 + LocalStorage 持久化
- **设计风格**：国网绿政企主题

## 🚀 快速开始

### 环境要求

- JDK 17+
- Node.js 16+
- Maven 3.6+

### 后端启动

1. 克隆项目到本地
2. 配置文件说明：
    - 项目提供 `application-example.yml` 作为配置示例
    - 复制示例文件为 `application.yml`，填入自身密钥
    - `application.yml` 已默认加入 `.gitignore`，不会被提交到代码仓库
3. 完整配置示例：
```
spring:
  ai:
    openai:
      base-url: https://api.deepseek.com
      api-key: 你的DeepSeek API Key
      chat:
        options:
          model: deepseek-chat
          temperature: 0.2
          max-tokens: 2048

tongyi:
  embedding:
    api-key: 你的通义千问API Key
    model: text-embedding-v2

# 可选：扫描件OCR配置，不需要可忽略
aliyun:
  ocr:
    access-key-id: 你的阿里云AccessKey ID
    access-key-secret: 你的阿里云AccessKey Secret
    endpoint: ocr.cn-hangzhou.aliyuncs.com
```
4. 执行 Maven 刷新依赖，启动启动类 `PowerSpecAiApplication`
5. 后端服务默认端口：`8888`

### 前端启动

1. 进入前端目录 `power-spec-ai-web`
2. 安装依赖
```
npm install
```
3. 启动开发服务
```
npm run dev
```
4. 访问地址：`http://localhost:3000`

### 接口验证

- 问答接口：`POST /api/spec-qa/ask`
- 文档上传：`POST /api/spec-qa/upload`

## 📦 部署方式

### 方式一：前后端合并部署（推荐）

1. 前端执行 `npm run build` 打包
2. 将前端 `dist` 目录下所有文件，复制到后端 `src/main/resources/static` 目录
3. 后端执行 `mvn clean package` 打 Jar 包
4. 启动命令（建议限制 JVM 内存，适配低配置服务器）：
```
java -Xms256m -Xmx768m -jar power-spec-ai-assistant.jar
```
5. 访问 `http://服务器IP:8080` 即可同时使用前端页面和后端接口

### 方式二：分离部署

- 前端打包后通过 Nginx 部署，配置反向代理到后端接口
- 后端独立 Jar 包部署，适合生产环境横向扩展

>
> **注意**：若使用 Nginx 反向代理且开启 OCR 能力，需调整代理超时时间，避免长任务被中断：
>
>
> ```
> proxy_read_timeout 300s;
> proxy_send_timeout 300s;
> ```

## 📝 注意事项

1. **向量库持久化**：内存版向量库仅用于开发调试，应用重启后上传的文档数据会丢失；正式使用请切换 Milvus 持久化向量库
2. **文档格式**：电力规范文档建议优先使用可复制文字的电子版 PDF，识别准确率最高；扫描件需配置阿里云 OCR 后方可入库
3. **密钥安全**：大模型 API Key、云服务 AK/SK 请妥善保管，生产环境建议通过配置中心或环境变量注入，禁止硬编码提交到代码仓库
4. **回答边界**：项目默认仅支持中文电力技术规范问答，超出知识库范围的问题模型会明确提示，禁止编造内容
5. **长任务处理**：多页扫描件 OCR 耗时较长，前端已做超时适配与等待提示；超大文档建议拆分后分批上传
